# mobile

Expo 57 / React Native 0.86.3 iOS client. Read `README.md` (run, stack, what is
shared) and `DESIGN.md` (rules) before changing a screen.

- **A decision lives in `shared/`; a client renders it.** If the web app also
  makes the decision, either move it into `shared/` or add a parity test there
  that imports the web module. Never fork a rule into a screen.
- **Nothing off the network is trusted**: responses go through a
  `plyr-shared/contract` parser; list parsers drop one bad record instead of
  failing the page.
- **Never touch `ios/`**: it is generated by `expo prebuild` and ignored.
  Native config goes in `app.json` or a config plugin.
- `bun install` runs at the repo root, not here.
- `just mobile check` must pass before a PR. It cannot prove playback; say what
  was run on a device or simulator and what was not.
- Audio: one `<Audio>` tag, keyed by track, rendered by `PlayerProvider`. The
  `AudioContext` is created on the first play so launching the app never stops
  other audio. Lock screen state is published on state changes and seeks, not
  every position tick.
